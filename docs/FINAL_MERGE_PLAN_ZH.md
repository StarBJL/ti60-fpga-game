### 1.2 路径差异及原因

- R6实测为 `square_path=3`：MOT2硬件运动＋SQTAB。运动更新与绘制读取同一张对象表，需要等待数据读取结束后再修改，当前方块路径不启用跨帧流水。
- final采用CPU运动＋三份FTAB表。CPU更新下一份表时，Blit可读取上一份已完成的表，逻辑与绘制可以重叠。
- R6已经具备CPU＋FTAB功能，但现有快速配置和部分预设仍选择硬件运动。具备某个硬件能力，不等于当前软件实际使用了对应路径。
- `ftab=1`、`vpipe=1` 等能力或设置标志，不能单独证明当前方块使用FTAB或流水；必须同时核对实际路径及流水生效状态。
- 引擎忙碌百分比是忙碌时间占采样窗口的比例，其中可能包含内部等待；不是XLR/RAM利用率，也不等于像素算术单元有效工作的比例。
- 优化目标是相同画面、相同工作量下提高实际吞吐、减少等待和欠流，不以强行达到100%忙碌占比为目标。

## 2．固定720p与硬件整改

1. HDMI有效输出固定为1280×720，保留R6配套720p像素时钟、同步极性、帧时序及HDMI音频参数。保留已有同步边沿处理，不因固定模式退回旧实现。
2. 删除1080p缩放器、三块扫描行缓存及不再使用的模式切换逻辑。保留720p正常扫描必需的FIFO、帧地址切换、硬件呈现计数、音频和输入寄存器。
3. 删除480p对照视图切换；东方默认并固定使用现有720p绘制视图。保留内部逻辑坐标或生成素材时使用的基础尺寸，不将其误认为480p输出功能。
4. 删除上位机的720p/1080p切换、试切换确认、恢复及仅服务该切换的兼容入口；删除实体键盘、矩阵及旧快捷键中的对应动作。
5. S15只保留状态/帮助，取消长按恢复720p；取消相关Fn显示模式组合。
6. 更新快速配置、预设脚本及控制协议。旧模式切换命令明确返回“不支持”，不能继续被预设调用，也不能误解释为其他动作。
7. 保留只读分辨率、输出尺寸及扫描状态，日志仍能确认实际运行720p。
8. 必须重新生成bit，并与ELF、上位机配套验收；旧R6 bit只作基线，不作为本轮最终交付。

## 3．方块、文字、指标、音频和场景显示

### 3.1 方块默认性能路径

- 默认采用CPU运动＋三份不可变FTAB表、分带绘制、源缓存、八像素混合和VSync跨帧流水。
- 使用R6现有紧凑对象格式及已预留的表空间，迁入final的初始化、尺寸分布、运动和透明规则，不再复制一套大对象数组。
- 三份FTAB的读写所有权必须清楚：引擎还在读取的表不能覆盖；配置变化的重建也不得覆盖在读快照。
- 保留MOT2＋SQTAB、CPU＋SQTAB、逐项提交三条对照路径，兼顾硬件运动的功能验证。
- 各路径使用同一批初始对象、随机种子、尺寸、颜色、透明度和运动规则；验证输出一致后再比较速度。
- 修改快速配置、默认设置和测试预设，避免再次强制切回MOT2。
- 保留逗号减少、句号增加数量，以及上位机100/10/1步进和自定义数量。
- 保留99999对象容量及原有尺寸能力，但不承诺任意尺寸、透明度和场景都能60帧。
- 以已有18000个混合尺寸方块的成绩作为回归目标，19000作为临界对照，不将20000或99999硬性标注为60帧预设。
- 实测记录实际绘制路径和当前流水是否生效，不能仅记录开关值。

### 3.2 中英文性能选择

不能仅凭两个版本的帧率差认定中文是根因。缓存命中后中文字形按图片复制，笔画主要影响生成阶段；稳态仍可能因为复制区域、字符数量、命令数量或缓存失效产生差异。

当前二倍字号下，英文字形约10×14，中文字形约16×16，但同一句话的字符数也不同，不能只按单字符面积推导总帧率。R6现有日志中字形缓存已稳定命中，没有反复清空。

实施要求：

- 同一份软件提供中英文切换，游戏逻辑、负载、刷新周期和绘图开关一致。
- 固定标题、提示和栏目预生成并缓存；动态区域只更新变化内容，避免逐帧生成全部笔画或重复格式化固定文字。
- 缓存发布、替换和清理遵守在途绘制的数据所有权，不覆盖引擎仍在读的字形。
- 使用DDR中的现有字形和标签缓存，不增加专用硬件字库或BRAM。
- 中英文预热后做相同条件对照。中文保持相同稳定60帧对象档位，且自由吞吐没有可重复的明显下降时，最终展示使用中文。
- 若中文降低临界数量或出现额外掉帧，最终展示默认英文。
- 不通过减少对象、关闭特效或隐藏统计使中文“达标”。

### 3.3 MS、FPS与忙碌占比

现有MS主要是“不含VSync等待的循环工作耗时”，可能包含引擎等待；流水时部分引擎执行还与其他工作重叠。因此“60 FPS、11.7 ms”不一定是除法错误，但标签容易让人误认为完整帧间隔或输入延迟。

| 指标 | 统一含义 |
|---|---|
| 呈现FPS | HDMI实际切换新帧缓冲的频率 |
| 渲染FPS | 软件完成并提交绘制的频率，与呈现FPS分开 |
| 平均帧间隔ms | 同一窗口实际呈现新画面的平均间隔；无新呈现时显示不可用，不伪造数值 |
| 工作耗时ms | 不含VSync等待的循环工作耗时，明确是否包含引擎等待 |
| 引擎忙碌% | 引擎忙碌时间占整个采样窗口的比例 |

- 呈现统计优先使用R6的HDMI硬件计数，保留重复帧和扫描频率。
- 详细面板保留逻辑、提交、等待、渲染及窗口最大耗时。
- 按渲染次数平均的工作耗时与按逻辑tick平均的逻辑耗时分开，不混用分母。
- 不将扫描频率当成游戏帧率，也不把工作耗时标成输入到显示的完整延迟。
- 场景或设置变化重开统计窗口，避免旧条件的数据污染新条件。

### 3.4 final音频与8MB限制

采用本地final的声音库、事件映射和播放规则，取消“必须保留R6十首音乐”的旧要求。

| 项目 | final已读取结果 |
|---|---|
| 实际音库 | `sound/sound_bank.bin`，包含头、索引及PCM数据 |
| 字节数 | 4,358,944字节，约4.36MB / 4.16MiB |
| 背景音乐 | 6首 |
| 音效 | 23种 |
| SHA-256 | `8e4f01fab424527102afdfab6e497bf9abc7f4c9f38b3ab90f5b7e77e1e79f2e` |

- 构建时检查实际音库严格小于8,000,000字节，该限制同时满足“小于8MiB”。
- 预览WAV及DDR预留区域大小不作为实际上板音库大小。
- 音库、播放驱动和游戏事件映射一起核对，避免只换二进制后出现找不到音效或错误播放。
- 上位机曲目列表、曲目总数及能力状态同步为实际6首，不保留失效的十首音乐入口。
- 保留东方、萝卜的背景音乐与打击音效；验证多人事件不会错播或重复触发。
- 保留R6硬件混音器、HDMI音频输出及配套时钟。final的低采样率素材由现有混音链路输出，不另存一套高采样率副本。
- 不为了满足音库限制删除已确认必须保留的游戏反馈；本地final现有库已低于限制。

### 3.5 图片与场景条形残留

- 图片切换保留R6原生1280×720生成和绘制，不能退回final旧的640×480居中图片。
- 四个场景均以720p帧缓冲为目标；东方保留原有比例和边侧布局，不做横向拉伸。
- 条形残留现有日志没有视频欠流证据，但根因尚未证实，不能直接认定已解决。

统一场景切换事务：

1. 在帧边界应用请求，停止提交旧场景的新工作。
2. 等待旧绘制，并处理排队翻页和待显示帧。
3. 清理待显示帧、绘制表、分带状态和必要的缓存状态。
4. 在空闲缓冲区完整绘制新场景，不直接清写正在扫描的画面。
5. 新画面完成后再翻页，并重置统计窗口。

必须通过复现和回归验收，不能只以“增加一次清屏”作为完成依据。

## 4．萝卜多人、东方单人、输入与遮挡

### 4.1 人数与独立状态

- 萝卜默认单人，不因手动移动、设备存在或关闭自动演示而自动变成三人。
- 菜单或暂停时选择1、2、3人，确认后开新局；运行中不直接改变实际人数。
- 单人支持上位机/电脑键盘及USB键盘操作P1。
- 双人P1使用上位机/电脑键盘，P2可选USB键盘或16键矩阵。
- 三人固定为P1上位机/电脑键盘、P2 USB键盘、P3矩阵。
- 未分配的设备不得误操作另一玩家；切换来源先释放旧输入。
- 压力模式继续单人，保留低、中、高、自定义第四档及现有尺寸、数量能力，避免合并时丢失入口。
- 不以人数整改改变当前压力发射规则；数量状态明确区分敌弹、玩家弹和合计。
- 东方采用本地final实现，只开放单人；删除多人入口和运行中自动启用多人的逻辑。

### 4.2 共享经验、共同升级、各自选奖励

- 全队只有一份经验、等级和升级门槛；拾取一颗经验只计入一次，不按人数倍增。
- 全队共同升级，各玩家分别选择自己的升级奖励；所有存活玩家完成选择后继续游戏。
- 各人的候选奖励和待选择状态独立保存，不能共用一组会被覆盖的选项。
- 生命、最大生命、受伤、无敌时间、装备、技能状态及分数保持独立。
- 倒下玩家不因共享升级自动复活；经验溢出保留并正确处理后续升级。
- 保留已确认的1～7级造型、皇冠、双枪和比例；更高等级沿用第7级外貌，不改现有正常关卡推进规则。
- 枪的朝向、枪口、子弹出生位置继续一致，不因遮挡整改改变武器坐标。

### 4.3 键盘与上位机整改

已有日志需区分：

- final的一段测试中，键盘报告增加且UART错误为零，但长期 `input_diag=1`，输入未交给角色。
- R6该次测试USB字节和矩阵事件为零，不能据此单独判断设备已连接、未连接或损坏。

提供“一键启用游戏输入”：

- 读取新状态，确认固件能力、诊断和校准状态。
- 按键松开后退出检测，收到对应确认后启用游戏控制并开启网页键盘捕获。
- 明确提示诊断模式、网页焦点、输入框、未启用捕获或失败场景造成的阻塞。
- 保留诊断、校准及未完成校准的保护，不擅自丢弃映射。
- 切换人数、来源或网页失焦时释放旧保持键，防止卡方向。
- 上位机停止指令不能覆盖实体键盘仍按住的状态。
- 设备事件为零时显示“尚未观察到输入”，不伪报成功或损坏。
- 保留消抖、校准和鬼键抑制，实测方向＋技能＋慢速组合。鬼键抑制不等于无二极管矩阵支持任意多键无冲突。

### 4.4 自然遮挡＋中心红点

- 身体与双枪始终位于弹幕下方，允许弹幕自然覆盖。
- 取消轮廓图、人物淡出，以及弹幕之后重新绘制脸部的保护效果。
- 遮挡达到80%时显示中心红点，下降至65%及以下隐藏，减少临界闪烁。
- 红点用少量不透明填充实现，不使用轮廓图片或透明混合。
- 红点跟随真实碰撞中心，不随人物装饰性上下浮动改变位置。
- 不删除弹幕、不挖避让缺口、不改变伤害和碰撞判定。
- 普通与压力模式都执行上述规则。
- 复用角色、双枪及弹幕的不透明掩码，将附近候选收集并入已有弹幕遍历，避免逐玩家全池重复扫描。
- 密集覆盖达到判定条件后提前结束局部计算；候选溢出必须正确回退并记录日志，不能误判。
- 红点绘制开销小，但80%检测仍有CPU成本，必须单独测量，不能预先宣称零开销。

### 4.5 16键矩阵示意

## 5．压力计时、控制接口与日志

### 5.1 计时行为

- 使用已有CLINT的64位硬件时间，不新增计时器硬件，不使用呈现帧数换算时间。
- 当前200MHz原始计数的32位低位约21.47秒回绕；使用已有64位读取接口处理长时间测试。
- 进入方块场景不自动计时，由“应用并开始计时”或对应测试预设按钮启动。
- 设置生效后从新测试段开始累计；正在计时的18000改为15000时清零并开始新段。
- 暂停停止累计，继续后接着计时；暂停中修改负载，清零并保持暂停。
- 萝卜、东方仅在压力运行阶段计时，普通游戏不启动压力计时。
- 实际在场弹数自然增加、减少不清零；改变目标数量、档位或测试条件才重开测试段。
- 同时记录目标数和实际数，不将尚未满载的时间当成满载稳定时长。
- 退出压力或离开场景结束该段，保留结果。
- 数量、尺寸、Alpha、绘制路径、关卡、VSync和语言等条件变化创建新段；固定分辨率状态只读，不再存在分辨率切换操作。
- 音量和展开帮助面板不清零；普通统计刷新不重置计时。
- 计时显示每秒更新一次，不忙等待，不增加高频中断。

### 6.2 DDR与软件内存

| 区域 | R6已有记录 | 整改方向 |
|---|---:|---|
| 程序、数据等 | 约8.65MiB/15MiB | 增加少量状态，删除大轮廓缓存，重新链接检查 |
| 音库 | 约6.79MiB/16MiB预留 | 改为final的4,358,944字节，限制实际库小于8,000,000字节 |
| 素材区 | 约17.25MiB/32MiB | 文字缓存使用DDR，避免重复分配 |
| 压力对象区 | 约29.80MiB/32MiB | 空间紧张，不复制整套大对象数组 |
| 四张720p帧缓冲 | 实际约7.03MiB | 保留，遵守显示/排队/绘制所有权 |
| 分带桶区 | 预留45MiB容量 | 保留，按实际配置核对边界 |
| 片上热数据 | 144字节/512字节预留 | 不扩展 |

- 三份FTAB已在DDR中预留；按99999项、每项8字节，三份约2.4MB，不再新增同等数组。
- 现有字形池约1MiB、标签池约384KiB，属于DDR占用，不是BRAM。
- 删除231种姿态的轮廓像素缓存，预计释放2,010,624字节、约1.92MiB DDR；用于80%判断的较小掩码继续保留。
- 音库由7,124,736字节改为4,358,944字节，减少2,765,792字节；节省DDR和下载体积，不直接释放BRAM。
- 表中区域占用和预留不是同一个含义，不应重复相加；最终核对链接结果、栈、素材、压力池、帧缓冲和分带桶区，确认无重叠。

### 6.3 术语与优化原理

| 名称 | 本工程中的含义 |
|---|---|
| 硬件运动/MOT2 | CPU之外的专用电路，读取DDR对象状态、计算移动和反弹，再写回；不是绘图引擎 |
| SQTAB | 本工程的方块表绘制格式，读取紧凑对象中的位置、尺寸和颜色等；运动和绘制当前共用同一对象表 |
| FTAB | 本工程的填充绘制表，记录位置、宽高、颜色和透明度，由Blit批量读取 |
| 跨帧流水 | CPU准备下一帧、Blit绘制当前帧、HDMI扫描已完成帧并行，依靠独立表和缓冲避免覆盖 |
| 八像素混合 | 支持的快速通路每拍混合八个RGB565像素，不是八颗子弹；逐像素A8仍有独立路径 |
| XLR | 用于控制、运算及寄存状态的逻辑资源 |
| BRAM/RAM块 | FPGA芯片内部的独立存储块，用于窗口、缓存、队列等 |
| DDR | 板外大容量内存，保存对象、表、音库、素材和画面 |
| DSP | 专用乘加硬件，用于部分像素混合等计算 |
| CLINT | CPU系统已有的硬件时间源，可读取64位时间 |

CPU运动路径也由Blit画像素，并非CPU逐像素绘图。三份表用DDR换取同时工作的机会；关闭硬件功能不会释放其已实现的BRAM，只有删除并重新综合才会改变硬件资源。忙碌占比高也可能包含DDR等待，因此不能用它单独判断性能优劣。

消抖用于过滤机械触点抖动；校准用于实体键与扫描位的对应；鬼键抑制用于可疑矩形导通组合，宁可暂时不响应也不输出误按键，不保证普通矩阵任意多键无冲突。
