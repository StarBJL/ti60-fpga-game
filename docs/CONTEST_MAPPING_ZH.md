# 赛题二：需求、实现和验收证据

本工程面向 **“基于 RISC-V 与 FPGA 异构架构的 2D 图形渲染加速引擎”**。条款来源为 [易灵思选题指南 PDF，第 7—9 页](references/contest_efinix_2026.pdf) 和 [8 月 22 日更正版 PDF，第 14—17 页](references/contest_2026_aug22_corrected.pdf)。后者明确使用 AXI4、DDR3、HDMI；本工程按这组更具体的条件说明。不要把另一道视频风格化赛题的 720p60 / 1080p30 要求误当成本题的最低门槛：**本题基础显示门槛是 640×480 @ 60 Hz**。720p / 1080p 切换是本工程扩展。

`源码已实现`、`离线测试通过`、`目标器件实现通过` 和 `实板验收通过` 是四种不同证据。本文件不把继承的位流、旧日志或主机模型当作 R5 的实板成绩。最终构建状态以 `BOARD_TEST/manifest.json` 和 `verification/r5/` 为准；用户后续将实板结果写入 [测试计划](BOARD_TEST_PLAN.csv)。

## 高阶挑战逐项映射

| 赛题要求 | 实现细节 | 验收重点 |
|---|---|---|
| 硬件 Alpha 混合 | `blit_engine.v` 读取目标像素、前景 RGB565 和可选 A8 平面，用硬件乘法完成各通道混合。整数约定为 `(src*a + dst*(256-a) + 128) >> 8`，不透明特例保证完整复制；支持全局 Alpha、逐像素 Alpha 和 additive 效果 | 不应仅看“开启透明”按钮。必须对 Alpha=0、半透明、不透明端点、A8 与 global 组合验证像素；报告 DSP 映射和目标器件 timing |
| Color Keying | 可配置透明色寄存器 `KEY`，默认 RGB565 品红 `0xF81F`；命中透明色的像素不覆盖目标。Alpha 和色键可以同时使用 | 用不规则边缘精灵叠加棋盘背景；验证透明色不污染背景，透明轮廓无矩形边 |
| 高负载互动游戏 | 萝卜玩法：七级角色、双枪、经验/升级、主动环形技能、敌人/敌弹与遮挡定位。东方式玩法：射击、低速、Bomb、关卡/Boss、压力模式 | 演示真实输入、技能、死亡/重开、升级选择，不能仅播放静态视频 |
| Alpha + Color Key 下挑战稳定 60 FPS 元素数 | 提供数量 100/10/1 步进、尺寸档位、CPU/HW / Alpha / VSync 控件，以及统一 M4/F4/P4/C4 测量窗口 | **以 720p60 模式测量**；1080p30 物理输出最多约 30 个不同画面/秒，不能把它当作 60 FPS 挑战成绩 |

## 从输入到画面的实际流程

1. 浏览器串口控制、终端兼容键、矩阵键盘和 CH9350L 解码进入公共语义控制；保持态与一次性动作分离。数量调节不会让同一动作被各输入源重复解释。
2. CPU 执行逻辑、碰撞、升级等工作，并构造绘制表。精灵图、美术、音库和 framebuffer 保存在 DDR3；这些空间不等于片上 block RAM。
3. 硬件读取命令、图像和位置表，执行 COPY/FILL/Key/Alpha。分带模式先把一个小窗口留在片上，按画层顺序合成，再写回 DDR，减少反复读改写背景的开销。
4. HDMI DMA 扫描已完成的 framebuffer；新的帧只有在安全交换点发布。R5 的 1080p30 输出仍以 **1280×720** 为渲染画布，用 **3:2 最近邻放大**输出 1920×1080。分辨率切换是真正的视频时序切换，但不是原生 1080p 渲染。
5. HDMI 音频混音器从 DDR 音库取样；场景音乐复用原声部和混音器，切曲不增加一套 FPGA 音频硬件。

## 上限的正确表述

| 项目 | 当前容量/边界 | 不能由此推断 |
|---|---:|---|
| 萝卜自定义压力敌弹池 | 40,000 | 40,000 弹可以稳定 60 FPS |
| 东方压力敌弹池 | 16,384 | 任意密度、尺寸、轨迹都能实时 |
| 方块对象池 | 30,000 | 30,000 个大尺寸半透明方块可稳定 60 FPS |
| 逻辑画布 | 1280×720，RGB565 | 1080p 输出具有 1920×1080 的独立细节 |
| 音库区域 | 16 MiB；R4 音库 10,123,520 B / 33 条目（10 首原创 BGM + 23 个音效） | 这是片上 RAM 占用，或支持任意长度无损音乐 |
| 原分带窗口 | 16 行，1280 px，历史实现 40 个 RAM block | 新 RTL 的实际映射必然保持相同块数 |

元素数量、覆盖面积、透明混合比例、绘制顺序、逻辑复杂度和 DDR 竞争共同决定稳定上限。数量翻倍不是唯一压力；方块边长翻倍会使理想覆盖面积变为四倍。压力弹体尺寸目前只改变显示，碰撞半径/伤害/速度保持原玩法，测试时需写明。

## 哪些数据已有证据，哪些需要补

历史 R2 的实际串口日志保存于 `logs/20261023/uart_20261023_204925_104_COM5_c91971_720P-R2.txt`。可作为演进基线，不能标成 R5 测试：萝卜约 16K 敌弹的短测约 60.3 render FPS；40K 约 20 FPS；方块约 8.8—8.9K、透明开启时约 60 FPS；20K 方块约 20 FPS。不同测试窗口的设置并不完全相同，严谨排行榜应按下面的统一协议重新测量。

历史 R2/R4 位流资源：XLR 55,848 / 60,800，RAM 253 / 256，DSP 32 / 160；200 MHz setup slack +0.053 ns、hold +0.025 ns。这组数仅说明旧版资源紧张。R5 已按新 Efinity 报告完成目标验收，最终对照见下表，不能沿用旧数当作新版本结论。Vivado 的通用 RTL 仿真可以发现功能错误，无法证明 Ti60 的实际布局、RAM 映射或时序。

R4 的离线字库测试显示标题页预热后每帧字库发布从 59—60 次降为 0、缓存重置从 1—2 次降为 0、拷贝调用从 109 次降为 63。它证明重复工作减少，**不等于测得了实板 FPS 增益**。新功能的离线测试、构建结果和硬件实现报告应与这些历史证据分开。

## 最终 Ti60 目标实现结果

Efinity 2026.1 已完成最终 map、interface、布局布线和 bit 生成。报告中的全部受约束时钟关系 setup / hold 为正；核心保持 **200 MHz**。

| 指标 | 历史 R2 / R4 | 最终 R5 | 变化 |
|---|---:|---:|---:|
| XLR | 55,848 / 60,800 | **58,518 / 60,800（96.25%）** | +2,670 |
| 片上 RAM block | 253 / 256 | **253 / 256（98.83%）** | 总量不变，仍余 3 |
| DSP | 32 / 160 | **32 / 160** | 不变 |
| core 200 MHz setup slack | +0.053 ns | **+0.118 ns** | 改善 0.065 ns |
| core 200 MHz hold slack | +0.025 ns | **+0.028 ns** | 改善 0.003 ns |

Blitter 两处浅队列确实释放 **4 块 RAM**，新显示扫描缓存使用 3 块，CH9350 UART RX FIFO 使用 1 块，因此整机是 `253 − 4 + 3 + 1 = 253`。这是为新增功能腾出空间，不是整机 RAM 使用下降 4 块。通用 Alpha 仍是每拍两像素，本轮没有声称已扩展为 4/8 像素 Alpha。

最终 `ti60_r5.bit` 为 **2,811,948 B**，SHA-256：`25dc85470b3f73f929ef75c60eb06880a7c46533f30c26820a40eb5def85ac83`。该结果证明本次受约束目标实现通过，不等于已测得板上最大稳定元素数、温度、功耗或外设兼容性。所有实板验收仍待用户填写。

## 推荐的 60 FPS 极限测量协议

1. 固定 bit/ELF 的 SHA-256、场景、种子、尺寸、Alpha、色键、VSync、CPU/HW 后端、运动后端和 table 模式。debug ELF 用于取数；release ELF 另测开销差异。
2. 720p 模式预热至少 10 s；每个设置采集至少 60 s。长稳测试另记录 10 min。先以 100 递增，接近失败点后用 10，再用 1 搜索。
3. 同时观察 `render_fps`、`logic_hz`、`present_fps`、`scan_hz`、`repeat_hz`、视频/音频 UF 增量、循环最大工作时间及引擎错误。扫描约 60 Hz 本身不能证明 60 FPS。
4. 稳定门槛建议：实际呈现接近扫描率、无持续重复帧增长、逻辑满足预期更新率、UF 增量为 0、无对象/列表溢出或引擎错误。采样窗口、允许误差和统计方法写入结果，不只挑选最好的一秒。
5. 在临界点回退一档复测，重复三次，保存原始日志、配置事件、CSV、显示视频和显示器模式信息。占满池但未发射出足够弹体时，以实际活动数量为准。

本工程不预填新 FPS、时延、功耗或温度成绩。`BOARD_TEST_PLAN.csv` 的测量值、结果、证据路径留空，供用户完成上板验收后填入。
