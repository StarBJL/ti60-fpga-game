# 08 — 资源、时序与压力测试（既有报告结果）

**数据来源：** 用户提交的《基于 Ti60 的万级弹幕游戏平台》技术报告，第 26 页资源/时序图与第 30～32 页压力测试表。本页面**转录已报告结果**，不是本次仓库重构重新运行的 Efinity 或实板测试。对应摘要：[timing_summary.json](evidence/timing_summary.json)、[hdmi_sync_build.json](evidence/hdmi_sync_build.json)。

## 1. PPA 资源与时序

| 资源 | 使用量 | 占用率 |
|---|---:|---:|
| 物理逻辑单元 XLR | 56,479 / 60,800 | 92.89% |
| 片上 RAM 块 | 250 / 256 | 97.66% |
| DSP | 56 / 160 | 35.00% |

目标核心频率 225 MHz；报告中的 core setup slack = **+0.063 ns**，core hold slack = **+0.012 ns**。机读时序汇总还记录其余六组 setup/hold 均为正值，但不代表所有未约束路径都被覆盖，也不能直接换算成跨温度/电压的实板稳定保证。高 RAM 占用和较小核心余量是后续重构的主要约束。

## 4. 测量口径与重新验证要求

1. `render_fps` 是软件已提交/完成渲染的节奏，`present_fps` 表示新画面被翻页呈现，`scan_hz` 是 HDMI 固定扫描节拍；出现重复帧时不可把三者等同。
2. 固定 BIT/ELF SHA256、Efinity 版本、seed、输入路径、人数、对象尺寸、Alpha 占比、负载档位和统计窗口。
3. 同时记录平均/最大帧时间、p95/p99、`logic`、`submit`、`qstall`、`tail_wait`、`vsync_wait`、DDR beat 与欠流。
4. 提供原始 UART CSV、示波/视频证据、时间戳和报告/源文件引用，测试失败亦应保留。
5. 做 CPU 与 HW、分带/非分带、缓存开/关 A/B 时，保持同样输入和相同版本，不从不同演示条件拼接“加速倍数”。
