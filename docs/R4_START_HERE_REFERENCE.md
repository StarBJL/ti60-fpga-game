# Ti60 R4：Linux 实验台、统一输入、尺寸档位与原创音乐

固件版本：`720P-R4-CONTROL-LINUX-20261023`。基于完整 R3，保留七级萝卜、双枪、主动技能和遮挡轮廓，以及 R2 的 720p 显示、东方、方块、图片与音频硬件。

## Linux 上位机

在新工程目录运行：

```bash
./Start_Control_Panel.sh
```

也可以运行 `python3 tools/control_panel/server.py --open`，默认打开 `http://127.0.0.1:8765`。端口已占用时追加 `--port 8766`。

依赖 Python 3.10+、浏览器及 pyserial。缺少 pyserial 时，可运行：

```bash
python3 -m pip install --user -r tools/control_panel/requirements.txt
```

选择 `/dev/ttyUSB*`、`/dev/ttyACM*` 或实际设备路径，波特率 115200，点击“连接并记录”。打开页面不会连接串口。程序先被动识别固件；识别到 R4 的就绪帮助或遥测后，才启用扩展命令。旧 R2/R3 固件仍可记录原始日志，不会向旧固件自动发送可能被误解的扩展命令。

连接后自动保存原始串口文本、带时间戳的操作事件和指标 CSV，位于 `logs/r4/日期/`；`logs/r4/latest.json` 指向最近记录。支持新建记录、备注标记、清空显示及导出。清空显示不删除磁盘日志。串口打开失败时界面显示具体错误；确认当前用户有设备访问权限，并关闭占用同一端口的旧工具。

Windows 可使用 `Open_Serial_Log.cmd` 启动同一 Python 控制台；本轮实际验证环境为 Linux。原 PowerShell 工具作为历史入口保留，新增功能以本控制台为准。

## 本次完成的功能

### 统一输入与数量控制

串口兼容键、带编号的控制命令及按住键状态进入统一控制路径；复用同一按键状态接口，供后续矩阵键盘或 CH9350L 解码器接入。当前位流尚未新增实体键盘／CH9350L 引脚接口。

- **数量步进支持 100 / 10 / 1**，增加、减少按钮和对应 `+ / -` 使用当前步进，也可以直接填写数量。
- 方块范围 **1—30000**。
- 萝卜自定义敌弹上限 **1—40000**；低／中／高档的既有配置保留。
- 东方压力敌弹上限 **1—16384**；上限调整与密度倍率分开，手动修改上限会关闭自动负载调节。
- 弹幕设置的是上限，新增弹体仍由原发射逻辑生成；界面区分“实际在场”和“目标上限”。降低上限会收紧现有池，增加上限不会凭空生成弹体。
- PC 键盘支持组合键、按下／松开、300ms 固件超时释放；浏览器失焦和串口断开时主动释放。超时后保持所有键松开，不回退成自动射击；再次收到普通终端方向字符时显式切回终端控制。

上位机启用“键盘控制”后：WASD／方向键移动，Z 射击，X／J 技能，Shift 低速，Enter 确认，Esc 暂停。**F6 / F7 / F8 对应 100 / 10 / 1 步进。** 也有可按住的方向、射击和低速按钮。

### 弹幕与方块尺寸

| 对象 | 档位 | 生效范围 |
|---|---|---|
| 萝卜压力弹体 | 9 / 13 / 17 / 25 px | 压力模式；普通模式沿用 R3 弹体 |
| 东方压力弹体 | 75% / 100% / 125% / 150% | 离散压力弹体，保持各弹型朝向和中心 |
| 方块 | 随机 6—40 px，或固定 6 / 8 / 12 / 16 / 24 / 32 / 40 px | 方块场景 |

弹幕尺寸是显示档位，碰撞半径、伤害、速度和轨迹没有随之改变；激光束宽度仍沿用原玩法。萝卜遮挡定位使用当前尺寸的实际不透明像素，避免轮廓判断与画面不一致。

切换前等待硬件空闲，切换后重建或失效对应绘制表并发布源数据。萝卜各档在启动时预生成；东方在设置改变时生成独立尺寸贴图，运行帧不进行软件逐像素缩放。方块直接使用原 MOT2 / SQTAB 对象中的大小字段，更新边界和面积统计。

### 字体与静态界面

中文 UI 换为 Noto Sans CJK SC Medium 的单色字形子集，保留像素数字字体，统一中英文数字的行内垂直对齐；东方分数、火力等数值改为统一右边界。字体许可和生成参数在 `ART/UI_R4`，再生成脚本为 `tools/build_ui_font.py`。

字库只在真正遇到 ASCII 时才生成 ASCII 图集；字体缓存位于原有 DDR 美术区域，静态标题和菜单文字另存为不可变贴图。相同标题页的离线调用对照结果：

| 指标 | R3 | R4 预热后 |
|---|---:|---:|
| 每帧字库发布次数 | 59—60 | 0 |
| 每帧字体缓存重置 | 1—2 | 0 |
| 每帧拷贝调用 | 109 | 63 |

证据为 `verification/r4/font_baseline.log` 和 `font_optimized.log`。这些是实际 C 路径的离线操作计数，不是实机帧率测试。

### 音乐

加入 **10 首原创像素风循环曲**，分别用于菜单、东方关卡、Boss、萝卜、压力测试和图片展示；各场景可点击“下一首”轮换。23 个原音效数据保持一致。

新音库共有 33 个条目，大小 **10,123,520 B / 16 MiB**，已链接进两个 ELF。增加曲目使用既有 DDR 音库和混音器，没有增加 FPGA 声部或片上 RAM。首次 ELF 下载比 R3 更大。

源码与波形位于 `sound/original_r4`，清单为 `sound/r4_sounds.txt`；30 秒试听合辑为 `sound/original_r4/preview.wav`。曲目由 `tools/create_original_music.py` 生成，没有使用外部歌曲或采样。切曲复用已有淡入淡出，暂停时保留当前场景音乐并降低音量。

## 指标的含义

所有场景使用同一测量窗口，配置或运行阶段变化后重新开始统计。

- **渲染循环 FPS**：CPU 完成渲染循环的速率；关闭同步时可能超过屏幕刷新率。
- **逻辑 Hz**：实际执行游戏更新的速率，不用渲染次数代替。
- **实际呈现 FPS**：HDMI 硬件的新画面计数除以真实窗口时长；不支持对应硬件计数时显示“—”。
- **扫描／重复帧率**：与呈现计数同一窗口归一化，不能把固定 60Hz 扫描当成 60 个新画面。
- **循环工作 us**：窗口内逻辑、提交及等待总时间除以渲染循环次数；流水模式下不是当前帧完整 GPU 延迟。
- **逻辑 us**：按逻辑更新次数单独归一化，另记录最大值。
- **视频／音频 UF**：当前测量窗口的增量，避免把启动时累计欠流误当成运行期间持续欠流。
- 调试版提供硬件忙碌与分带耗时；发行版对未采集的硬件剖析项标为不可用。

新协议为 `:请求编号 命令 [整数参数]` 加换行，回复 `ACK` 和 `S4/A4` 状态。`M4/F4/P4/C4` 四行通过同一个序号组成完整测量；缺失或混号的记录不拼接成假数据。默认紧凑输出，详细旧格式可在上位机开启。

常用命令示例：`:1 step 10`、`:2 count 14001`、`:3 delta -1`、`:4 bullet 17`、`:5 square 12`。东方的 `bullet` 参数为百分比。`scene` 为 0 东方、1 萝卜、2 方块、3 图片；`stress` 在萝卜取 1—4，0 打开菜单。`period` 设置图片切换间隔 1—60 个渲染帧。

## 接下来的软硬件优化

本版首先移除了已复现的字库重复工作，并建立可对照的输入、尺寸和指标体系。**当前 bit 没有变化，所以不能把软件改动称为已改善 FPGA 时序或片上资源。** 继承 R2 的报告仍是 XLR 55,848/60,800、RAM 253/256、DSP 32/160、200MHz setup +0.053ns / hold +0.025ns。

| 优先级 | 方向 | 依据与验证要求 |
|---|---|---|
| 1 | 用 R4 实板日志建立同条件基线 | 固定场景、尺寸、数量、透明和同步状态；同时比较渲染、逻辑、实际呈现、最大工作时间和 UF 增量；预热后确认字体生成／重置不持续增长 |
| 2 | 萝卜敌弹热循环与数据布局 | R2 40K 时敌弹更新约 29.6ms；评估紧凑字段、顺序访问、活动索引与重复计算，保持轨迹、碰撞、计数和绘制表内容一致 |
| 3 | 方块 Alpha 合成通路 | R2 8.9K 方块透明开约 60FPS、关闭约 96FPS 的短测显示合成成本显著；评估复用当前窗口的 4／8 像素 Alpha 流水，利用 DSP 余量，避免复制整套引擎 |
| 4 | 读取额度关键路径 | 最紧路径 `u_blit/f_addr[1] → u_blit/rf_res[9]`；重排组合链和寄存器时保持 FIFO 预留、背压和突发事务守恒，并检查综合后网表，不能只看 RTL 仿真 |
| 5 | 释放片上 RAM | 当前分带窗口占 40 块，Sapphire SoC 占 125 块；评估较小分带高度／二维窗口和缓冲组织。更小窗口会增加分箱与 DDR 工作，不能只按节省块数判断收益 |
| 6 | 再做分辨率和以太网 | 720P60／1080P30 可评估共用显示时钟，但仍需重排帧缓冲、行宽、分带数量及 60Hz 逻辑调度；板载以太网需先裁剪 MAC/FIFO 并留出资源 |

这些是下一阶段的具体工作项，本轮没有改动 RTL 或进行新的综合／布局布线，也没有承诺 40K 弹或 30K 方块能达到 60FPS。
