# 720p 合并修订版 R2：中文、全屏、音效与第四档

启动版本：`720P-MERGE-R2-ZH-FULL-20261023`。本目录是独立修订版，第一版 `Ti60_720p_SQUARE20K_MERGE` 及其完整日志保留。**R2 已离线编译及验证，尚未下载板卡；R1 的板测结果不能作为 R2 帧率。**

## 上板文件与日志入口

- `BOARD_TEST\720p_merge_r2.bit`：本版配套位流，方块硬件容量扩至 30K。
- `BOARD_TEST\720p_merge_r2_debug.elf`：首次验收使用，保留详细统计，已链接声音库。
- `BOARD_TEST\720p_merge_r2_release.elf`：精简统计版，配用同一 bit，也包含声音库。
- `BOARD_TEST\720p_merge_r2_debug.launch`：修正为本目录路径的 RISC-V IDE 配置。
- **`Open_Serial_Log.cmd`**：双击打开本版日志窗口；默认 115200 / 8N1，选 COM 后“连接并自动记录”。记录在本目录 `logs\日期\`，版本标记默认 `720P-R2`，`logs\latest.json` 指向最新记录。

先下载本版 bit，再下载本版 ELF。确认启动版本名和 `native square load max 30000`；不要与第一版 20K bit 混用。日志工具不会自动连接串口或发送指令；连接前关闭旧日志窗口，释放同一 COM 口。

## 本次修改

1. 屏幕菜单、字幕、状态及符卡名称改为简体中文。调试串口保留英文标识，便于对照历史数据；按键名、CPU／TI60 等型号及单位缩写保留必要标记。
2. 方块场景的 **英文半角逗号 `,` 减 100，英文半角句号 `.` 加 100**，范围 **100～30,000**。`@` 仍进入 20,000 方块基准；`- / +` 保留原来的大步减半／加倍，最终夹紧到容量。屏幕下方显示微调提示。
3. 萝卜和图片切换改为 **原生 1280×720 绘制**。图片直接生成 1280×720，三张分别位于原有三个 2MiB DDR 槽；萝卜扩大活动场地、重排 HUD 和菜单，基础精灵在启动时等比缩放，避免每帧软件拉伸。东方默认原生 720p，原 `#` 诊断切换保留。
4. 东方继续保留音乐及打击音效；萝卜新增标题／战斗／首领背景音乐，以及射击、命中、击杀、受伤、升级、暂停、结束提示。复用现有音库，带音效触发间隔限制。方块和图片不再自动播放 BGM；主动试听和测试音仍可使用。
5. 萝卜恢复 **第四档自定义压力**：40K 敌弹容量，`- / +` 每次调整 1000，最低 1000。低／中／高档仍为 1024／2048／4096。这里是敌弹池上限，实际在场数受生成和消失影响，不代表立刻灌入同样数量。

R19 的升级人物、双枪及遮挡轮廓没有合入；R19 的 1.4W 帧率问题留待本版验收后单独处理。本次基础精灵的等比缩放属于分辨率适配。

## 快速验收顺序

1. `n` 在东方、萝卜、方块、图片场景间切换，检查四个场景都使用全屏布局；图片连续切换不应留下小屏黑边。东方主动发送 `#` 可退回旧尺寸诊断视图，复核全屏时请切回原生模式。
2. 萝卜场景发送 `l` 打开压力菜单，菜单应显示四项；按 `4` 进入自定义。`l`／`4` 会退出自动演示，避免菜单被自动驾驶选走。游戏中按 `4` 也可直接进入自定义。`- / +` 调整敌弹池上限，`m` 回菜单。
3. 萝卜普通游戏确认有背景音乐，靠近并攻击怪物确认射击／命中／击杀音效；暂停时 BGM 降低音量。再切回东方，确认其背景与打击音效保持。
4. `@` 进入 20K 方块；使用日志窗口“方块减100 ,／方块加100 .”逐步接近临界点。切换后先等两三个统计窗口稳定，再记录至少 30～60 秒；将透明、同步、绘制和运动模式一起记录，不能只比较对象数量。
5. `&` 核对同初始状态下的 CPU／硬件运动，期待 `exact PASS`；`!` 只切换运动，`%` 只切换表读取／逐个调用，`g` 切换整套绘制后端。上限已实际扩展到 30K，运动模块及 SQTAB 都支持，不是只改软件显示数。

**音频按键调整：**日志窗口的“测试音”按钮发送左括号 `(`，“总音量”发送右括号 `)`，`/` 试听音库。逗号／句号在方块场景优先用于数量微调，其他场景保留旧音频兼容行为；使用括号按钮可避免歧义。测试完应关闭测试音，查看 `vol` 不为 0，再听游戏。普通换场景会关闭测试音。

## R2 离线结果与边界

- 最终硬件 map／interface／pnr／pgm 通过；核心 200MHz，setup `+0.053ns`，hold `+0.025ns`，CDC 无同步器告警。
- RAM **253/256（98.83%）**，XLR **55,848/60,800（91.86%）**，DSP **32/160**。
- 软件 debug／release 编译通过；主 DDR 静态链接占用约 **11.8MB / 15MiB**，音库约 2.12MB、美术区约 10.05MB 各在独立区域。没有继续缩 CPU Cache。
- MOT2：7 组，包括 20K、30K 连续两帧、反弹、直方图、容量拒绝、读写错误；生产 ELF 的 CPU 运动 20K 输出也通过独立参考。
- SQTAB：5 组完整 1280×720 RGB565 对照，包括 20K 和 30K；大容量组使用 6 像素方块，65 对象组覆盖 6～40 像素。**大容量仿真不是生产混合尺寸负载的帧率测试。**
- 原生萝卜：四档、1K～40K 调整、坐标边界、13 像素敌弹、三份 DMA 绘制表及帧缓冲护栏通过。三份表保留 720p 分带流水的缓冲安全，不采用供体旧版两份表。
- 东方：中文框架／菜单、600 次逻辑更新及帧缓冲护栏通过。图片：三个原生图槽及 30K CPU 绘制的边界护栏通过。
- 萝卜音频事件映射、重复触发限速、BGM／暂停／结束状态测试通过；原混音器→HDMI 缩短光栅仿真及最终综合网表计数器 3000 向量检查通过。**这些不能代替实板听音及长时间 DDR 竞争验收。**

`verification` 下的 PNG 来自实际 C 渲染器离线输出；其中 FPS／耗时是测试填入的示例值，不能作为实板成绩。`BOARD_TEST/manifest.json` 保存文件及源码 SHA-256；资源和时序原报告也放在 `BOARD_TEST/reports`。
