# 间歇性闪烁排查记录（2026-10-02）

## 当前判断

用户观察到整屏或大块区域反复变黑、变亮，CPU 后端也会出现；现象有时出现、有时不出现。目前只有新显示屏，无法做旧屏与新屏的对照。随后用户报告：将 HDMI 线插紧后，闪烁停止。

这使 HDMI 插头接触或线缆连接成为当前最有力的怀疑方向，尚未经过长时间板上复测，不能宣称已经证明根因。先固定连接，保留原调试代码，在相同场景持续运行，观察是否复发。无需根据现有证据修改渲染或缓冲切换逻辑。

## 已取得的证据

- 用户日志中 HDMI 帧计数约 59–61 次/秒，`uf` 始终为 0。该计数监测 FPGA 内部显示 FIFO 欠载，不监测显示器端的信号锁定和插头接触状态。
- CPU 后端也闪烁，因此不能只归因于 Blit 引擎。
- 大多数高负载日志中 `qstall=0`，帧尾等待约 2 us，队列末尾占用很小；没有持续命令队列堵塞的证据。
- 部分日志存在游戏逻辑耗时突增；它可以解释卡顿，但不足以解释整屏黑亮闪烁。
- 源码中提交显示前，硬件路径调用 `blit_wait()`；三缓冲选择排除当前显示缓冲和上次提交缓冲。此次检查没有发现能够直接解释闪烁的缓冲覆盖问题。

| --- | --- | --- |
